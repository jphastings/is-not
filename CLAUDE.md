# is/not

atproto appview for `at.isnot.review` records. Go API at the root, SvelteKit site in `web/`, lenses in `packages/lenses`.

## Where things are

- Architecture and how to run: `README.md`. Decisions: `docs/superpowers/specs/`. What is done and what is next: `beans list` (epic ISNOT-kgev). Lens authoring: `docs/creating-a-lens.md`.
- The repo is `jphastings/is-not` on GitHub. The site is live at `isnot.at` and the API at `api.isnot.at`; `@is-not/lenses` is not published yet. `.github/workflows/lenses.yml` publishes both `@is-not/lenses` and `@is-not/sentence` with npm trusted publishing (no token). Every package needs its own trusted publisher on npmjs.com naming this repo and `lenses.yml`, allowing the `npm publish` action; a missing publisher answers 404 on the PUT and a disallowed action answers 403 "OIDC permission denied". Don't rename that workflow file: the publisher configs name it. A package's very first version has to be published by hand, because a publisher can only be attached to a package that exists once a version PR is merged; until the first release exists `scripts/fetch-lenses.sh` has nothing to fetch, so build the wasm locally. Trusted publishing only works once a package's first version already exists on npm: for any new package (`@is-not/sentence` included), JP publishes that first version by hand (`pnpm publish` in the package dir) before CI can take over.
- Deployment: one Railway service from the root `Dockerfile`, declared in `.railway/railway.ts` (see README "Deploying"). Never run `railway config apply` without JP saying so; `railway config plan` is safe. Custom domains cannot be declared in the IaC file: add them in the dashboard and `railway config pull` them in.
- The project's atproto identity is `did:web:isnot.at`, served from `web/static/.well-known/` (`did.json` and `atproto-did`). The repo lives on `eurosky.social`, and the `#atproto` key in `did.json` must match the signing key that PDS holds for the account (`com.atproto.identity.getRecommendedDidCredentials` reports it), so moving PDS means editing `did.json` in the same change. `com.atproto.server.reserveSigningKey` is a dead end here: creating a local account mints a fresh key and ignores reservations. `web/static/.well-known/` survives the build because sirv makes an explicit exception for `.well-known` under its no-dotfiles rule.

## Working here

- Work happens on branches, in parallel, and lands through pull requests against `jphastings/is-not` (`gh` is authenticated). A piece of work gets its own git worktree so several can run at once without touching each other's files; give each agent an explicit list of the files it owns and the files another agent is in, or two of them will edit the same component and the merge will be yours to untangle.
- A branch cut before a sibling landed will not have that sibling's work. If two branches need the same helper, land it on `main` first and tell both to reuse it: an agent that cannot see a function it was told to use will recreate it, and the merge then conflicts on a file neither side meant to touch.
- Read a merged branch before trusting it, and run the checks yourself on the merged tree. An agent verifies in its own worktree, where the wasm, the `dist/` builds and the paraglide output are its own; `main` after a merge is a combination neither agent tested.
- `.claude/worktrees/` holds whole copies of the repo, so a tool pointed at the repo root reads them too. `vite.config.ts` ignores that path for exactly this reason: `pnpm check` was reformatting vendored lexicons inside stale worktrees.
- Run `go test ./...` before committing. The smoke test in the ingest plan needs network access.
- Keep this file focused: only things that cost real time, or how development is done here. After each piece of work, check whether it needs updating and make the edit in the same commit.
- Migrations in `migrations/` are append-only: the site is deployed, so a live database exists. Editing an applied file changes nothing on that database (the runner skips versions it has already recorded) and the mismatch only shows up as a missing column at runtime. Add a numbered file instead.
- Editing a file in `lexicons/` changes nothing for anyone else until it is republished as a `com.atproto.lexicon.schema` record: `goat account login -u isnot.at`, then `goat lex publish ./lexicons`. `goat lex status ./lexicons` says whether the network matches the files, `goat lex check-dns ./lexicons` checks `_lexicon.isnot.at` resolves, and `goat lex breaking` checks an edit against the evolution rules before it goes out.
- The Go build embeds `packages/lenses/dist/isnot_lenses.wasm`, which is git-ignored. Before `go build` or `go test`, either build it (`sh packages/lenses/build-wasm.sh`, needs rustup with the wasm32 target and wasm-opt) or download the released one (`scripts/fetch-lenses.sh`).
- Never show an at-uri to users as a title or in running text: it means nothing to them. Show the subject's title, or a muted placeholder while it resolves (`/reviews/[...id]` shows "Finding…"); an at-uri is only displayed where showing one is the point.
- The site's design context is `PRODUCT.md` and `DESIGN.md` at the repo root (impeccable); read them before changing how anything looks.
- JavaScript lives in a pnpm workspace with Vite+: `pnpm install`, `pnpm test`, `pnpm check` (oxlint and oxfmt, configured in the root `vite.config.ts`; no prettier, eslint or biome). oxfmt does not format `.svelte` files; `pnpm --filter web check` type-checks them. Package versions use changesets (`pnpm changeset`). The site in `web/` must stay runnable without `node_modules` (adapter-node build, `node:sqlite`, everything in devDependencies) because the runtime image copies only `web/build`.
- Anything that changes what the container needs (new Go embed, new build input, new env var) also changes the `Dockerfile`, `.dockerignore` or `.railway/railway.ts`. `docker build .` is the check (colima on JP's Mac: `colima start`).

## Things that cost time

- Jetstream v2 archive replay is metered and needs `JETSTREAM_API_KEY`; the live tail is free with a 36 hour cursor lookback. See `docs/superpowers/specs/2026-09-13-ingest-design.md`.
- Without an API key, a persisted cursor older than the live lookback window (36 hours) makes the client fail fatally on every restart. Delete the row in the `cursor` table to resume from the live tip, or set `JETSTREAM_API_KEY`.
- Homebrew's cargo shadows rustup on JP's Mac and cannot target wasm32. `build-wasm.sh` forces rustup's toolchain; do the same for any new Rust build step.
- panproto's lens `get` drops ref-typed properties and `remove_field` fails on arrays (bean ISNOT-qvqp). Lenses name identifiers, and titles a step can't reach, in `extensions` instead (see `docs/creating-a-lens.md`).
- `wasm-opt --all-features` lets Binaryen rewrite calls into `call_ref` (the function-references proposal), which wazero's `CoreFeaturesV2` runtime can't instantiate even though Node/V8 accepts it. `build-wasm.sh` pins wasm-opt to wazero's actual supported feature set instead of `--all-features`; keep new Rust/wasm build steps on that same allowlist.
- The runtime image is `node:24-bookworm-slim`, which ships no CA roots; the `Dockerfile` copies `ca-certificates.crt` from the Go stage. Without it the static Go binary fails every TLS dial (jetstream, PLC) while the health check still passes.
- The Docker `rust` image has no toolchain called `stable` (rustup reserves the name and refuses to link one). `build-wasm.sh` takes `RUST_TOOLCHAIN`; the `Dockerfile` passes the image's active toolchain.
- The lenses' wasm only loads in the browser (`web/src/lib/lenses.ts`, which resolves it through Vite's `?url`). Calling `loadLenses()` from anything under `web/src/lib/server/` looks fine in dev and fails in production: the package's `new URL('./isnot_lenses.wasm', import.meta.url)` survives the SSR bundle unrewritten, and nothing copies the wasm next to `build/server/chunks/chunks/`, so every call ENOENTs. Resolve subjects client-side instead.
- atstore.fyi keeps every listing in its own repo, so resolving an import is N `getRecord`s against one PDS. A burst of them trips the PDS rate limit (3000/5 min), and the 429 carries no CORS header, so the browser reports it as a CORS failure, not a rate limit. The import page resolves rows one at a time, and `@is-not/lenses` caches DID→PDS per DID, for this reason.
- A new importer is a `preview(did, agent) => ImportRow[]` module in `web/src/lib/server/` (see `atstore.ts`, `bookhive.ts`) plus a registry entry in `web/src/lib/server/importers.ts` (`IMPORTERS`, read by `/import`'s availability check) plus a thin route under `web/src/routes/import/<domain>/` that hands `domain`, `sources` (key+label, in display order) and `defaults` to the shared `$lib/ImportPage.svelte`. The load/action boilerplate (sign-in, PDS-failure handling, the `?/import` form action) lives once in `importers.ts` (`importLoad`, `importAction`); labels are computed in the route with paraglide messages, not in the server module. A collection whose record just marks "I did this to that subject" (a like, a favourite, a recommend, with no opinion of its own) is `previewPresenceImport(did, agent, locale, collection, source, subjectOf)` in `importers.ts` — it dedupes by subject, keeps the earliest `createdAt`, and fills `existing`; see `gamesgamesgamesgames.ts`, `rocksky.ts`, `standard.ts` for the couple of lines each importer then needs. A collection where the record itself carries the opinion (a star rating) still wants its own module, one row per record — see `bookhive.ts`, `popfeed.ts`.
- Paraglide generates `web/src/lib/paraglide/` at build time, so a new message key only type-checks after `pnpm --filter web build` (or a dev server run).
- `list` (for a `<datalist>`) is only valid on `<input>`, not `<textarea>` — `svelte-check` catches it as a type error, but the underlying problem is that HTML has no native typeahead for a wrapping field. Every autosize field is a `<textarea rows="1">` (so long text wraps the sentence rather than scrolling), so a typeahead needs a hand-rolled ARIA combobox/listbox, not a `<datalist>`: see `SubjectField.svelte` for the pattern (debounced fetch with `AbortController`, `aria-activedescendant` instead of moving DOM focus into the list, `onfocusout` with a `relatedTarget` containment check instead of blur-then-click races). That check alone is not enough on touch or Safari: neither focuses a `<button>` on tap, so `relatedTarget` is null, the list closes on the tap and the click lands on nothing — the listbox cancels `pointerdown` so the field keeps focus through the tap. The list is anchored to the field, so near the right edge it would overflow the viewport and a phone widens the page to fit; an effect shifts it back inside after it renders.
- A `<select>` is always as wide as its widest option, and an `<input>`'s intrinsic width comes from its `size` attribute. `ReviewForm.svelte` sizes both to their current value with a hidden twin (`.autosize`): inputs need `size="1"`, and the select has to be taken out of grid sizing with `position: absolute`.
- Firefox sizes a form control taller than the same text, so an `<input>` left in a grid cell makes that cell taller than its neighbours: Chrome hid the bug entirely. `ReviewForm.svelte` positions inputs and selects absolutely so the hidden twin alone sets every box. The sentence's parts are told apart by ink, not chrome: the direction word is the one green, subject and adjective are underlined with `text-decoration` on the control itself (which needs no box of its own, so it cannot shift the layout).
- `text-wrap: balance` is ignored when a line is made of atomic boxes, so the homepage sentence's parts are plain `inline` spans that fade in, not `inline-block` ones that fly in. The `/review` sentence cannot balance for the same reason: its fields are `inline-grid`. An `<input>` also cannot wrap, so those fields are auto-growing `<textarea rows="1">` instead.
- The OAuth scope is the permission set `include:at.isnot.authManageReviews` (`lexicons/at/isnot/authManageReviews.json`). A permission set resolves only once published as a lexicon record, so editing that file changes nothing for any PDS until `goat lex publish ./lexicons` runs; a set may only name resources in its own NSID group or below. If sign-in or saving breaks, that is the first thing to suspect: `SCOPE` in `web/src/lib/server/oauth.ts` reverts to `atproto transition:generic` in one line. A session the server stops honouring reads as signed out rather than failing every save.
- `/reviews/[...id]` takes a DID, a handle, or a whole at-uri. A rest param keeps `at://`'s empty segment, so `/reviews/at://did:plc:x/nsid/rkey` arrives intact — but the load still rebuilds it from `at:/*` in case a client collapses the slashes. Most at-uris list all reviews of that subject; one whose collection is `at.isnot.review` is instead a single review's own canonical URL (`/reviews/at://<did>/at.isnot.review/<rkey>`, optional `?adjective=`) — the old `/reviews/[id]/[rkey]` route now just redirects there. That branch resolves a non-DID authority itself, so a handle in the at-uri still 302s to the DID form.
- `web/src/routes/oauth/login/+server.ts` and `oauth/callback/+server.ts` hardcode their redirects to `/review` (on both success and failure). Any other page that opens the sign-in popover sends the user back to `/review` once they're signed in, not back to itself; `oauth/switch` and `oauth/logout` do return to the page, via a hidden `next` path. The sign-in and accounts popovers (and the hidden login/switch/logout forms) live once, in `AccountMenu.svelte` rendered by the root layout behind the top-right avatar; a `popovertarget` anywhere (the `@who?` slot, the import page's sign-in button) reaches them by id, so don't add a second copy. `#accounts-popover` anchors to whichever button opened it (a popover's invoker is its implicit anchor), so never give it a named `position-anchor`: that pins it to one button on every page.
- `pnpm --filter web build` (and `dev`) resolves `@is-not/lenses` and `@is-not/sentence` as real packages, so each needs its own `dist/` built (`pnpm --filter @is-not/lenses build`, `pnpm --filter @is-not/sentence build`) before the site builds in a fresh worktree — `packages/lenses/build-wasm.sh` alone only produces the `.wasm`, not the JS wrapper `@is-not/lenses/dist/index.js` the web app imports.
- Svelte scopes `<style>` per component, so the `.autosize` sizing-twin trick (hidden `::after` twin, absolutely-positioned control, `line-height: normal` last) is duplicated verbatim in `TagRow.svelte` and `SubjectField.svelte`; A tweak to the twin needs both edited, not one; `:global()` was deliberately avoided to stop `.autosize`/`.option`/`.clear` leaking into unrelated markup. The twin's content ends in a zero-width space, never a real one: a trailing space widens the box and the rule runs on past the word.
- `review.ts` (not `lenses.ts`) owns `RECORD_URI` and subject-uri validation (three-part at-uri, `.profile`-NSID rejection via `checkSubjectUri`), so it stays free of `lenses.ts`'s top-level `?url` wasm import — pulling that into a pure validation module (or its test file) would make `review.test.ts` depend on the built wasm existing.
- A touch screen leaves the tapped element in `:hover` until the next tap, so any hover look that resembles an on/active state makes toggles appear one tap behind (the direction filter pills: tap one off, it stays moss until the next tap). Hover rules that change colour or background belong inside `@media (hover: hover)`.
- Form controls do not inherit `letter-spacing` (the UA stylesheet resets it to `normal`), but the `.autosize` twin does, so under the display heading's negative tracking a control's text ran ~0.5px per character wider than its box and the tail wrapped onto a hidden second line: `something?` showed as `something`. Every twin-sized control sets `letter-spacing: inherit` next to `font: inherit`; a `<button>` also needs `font: inherit` before any `em` size means the sentence's em.
- Gecko lays a `<button>`'s content out on an inline line box of the inherited font, so an SVG inside a small button sits on a baseline ~1em down and draws well below where Chrome draws it; give the SVG `display: block` and the button `line-height: 0`. `/Applications/Zen.app/Contents/MacOS/zen --headless --new-instance --profile <scratch> --screenshot out.png URL` gives a real Gecko render to check against; Chrome alone hides this.
- `ClearButton.svelte` is the one "×" affordance for a completed, removable sentence field: absolutely positioned over its `.autosize` parent (never reflows the sentence), hidden until hover/focus-within on desktop, always visible under `(hover: none)`. Reuse it for any new removable field instead of adding another mechanism.
- `node:net`'s `BlockList` is the right tool for an SSRF address guard (`web/src/lib/server/canonical.ts`) — it does IPv6 CIDR arithmetic for you, no hand-rolled parsing needed. But one instance mixes families internally: adding an IPv4-mapped IPv6 subnet (`::ffff:0:0/96`) to the *same* `BlockList` that also has IPv4 rules makes every plain IPv4 address match too, via its mapped form — `check('93.184.216.34', 'ipv4')` comes back blocked. Keep IPv4-mapped detection in a separate `BlockList` instance, queried only with family `'ipv6'`.
- A single review's page (`/reviews/[...id]`) falls back to a live PDS read (`web/src/lib/server/liveReview.ts`) when jetstream hasn't ingested it yet; `DEADLINE_MS`'s 3s came from timing two real sequential cold HTTPS requests (600-800ms each), not a guess. The PDS endpoint and a did:web DID's own host are both attacker-controlled, so both go through `canonical.ts`'s `guardedFetchJson`, not a bare `fetch` (plc.directory stays bare — a fixed, trusted host).
- The `/og.png` renderer (`web/src/lib/server/og.ts`) reaches its font and resvg wasm through `read()` from `$app/server` (`web/src/lib/server/ogAssets.ts`), not `new URL(import.meta.url)` — the same lenses-wasm lesson above applies to any server-only asset. `read()` doesn't run under vitest, so `ogAssets.ts` is mocked in `og.test.ts` and the real bytes come from `node:fs` instead. Its colours are hex copies of `app.css`'s oklch tokens (resvg can't parse `oklch()`); recompute them with the CSS Color 4 OKLab matrices, don't eyeball them, if those tokens change.
- opentype.js ships no `exports` map, so SvelteKit's postbuild step (which loads the built route directly under plain Node to check for prerender flags) resolves its CJS build and can't always see `parse` as a named export, even though Vite's own bundling (which prefers the `module` field) resolves the ESM build fine — a static `import { parse } from 'opentype.js'` broke only that one step. `og.ts` loads it with a lazy `import('opentype.js')`, read through the CJS interop's always-present `.default` as a fallback. opentype.js's `toPathData` also emits `NaN` for coordinates a hair off an integer (its rounding concatenates `"1e-15" + "e+2"`), and resvg silently drops the rest of a path at the first `NaN`, cutting words off mid-card: `og.ts` serialises `path.commands` itself.
- The `/reviews/` listings' type, adjective and direction filters are server-side query params (`type`, `adjective`, repeated `direction`), read by `+page.server.ts` and applied in the DB query, not client-side `page.state`. Pagination is keyset (`cursor`, opaque base64 of `(updated_at, did, rkey)`), not OFFSET, so a filter narrows the whole scope before the page boundary is drawn. Toggling a filter is an ordinary link navigation that resets the cursor.
- The duplicate-review merge job (`web/src/lib/server/mergeDuplicatesJob.ts`, pure merge logic in `mergeDuplicates.ts`, started from `hooks.server.ts`) lists each account's `at.isnot.review` records live from its PDS and writes the merge with `applyWrites`' `swapCommit` set to the repo head, so a concurrent write fails the call instead of being clobbered; it only covers accounts the server currently holds a usable oauth session for.
- `mergeTags` (`web/src/lib/review.ts`) was written for save-time conflict resolution but is also the right tool for merging a restored client-side draft into a person's just-discovered existing review: called with `prefilled: []` it's a pure union — a shared adjective (folded) keeps the offered spelling and direction, nothing is dropped. Already covered by its own tests ("never removes when the form was not prefilled"), so a draft-restore merge needs no new test.
- The site never shows a poster's identifiers. Subject title, type and identifiers come from `subjects`, which the ingester writes by fetching the subject record from its PDS and running the lenses (`ingest.go` `resolveSubjects`); the review's own `subject_title`/`subject_type` are only the fallback. A missing link on a subject page means the fetch or lens failed for that subject (grep the ingester log for its uri); saving the review again with a new subject cid retries it. Adding a link for a new identifier key is one row in `web/src/lib/identifierLinks.ts` and, for a new brand, a path in `BrandIcon.svelte`. `resolveSubjects` runs before the batch transaction, like handle resolution, so network time never holds the write lock. The startup backfill retries every subject without a `subjects` row on each boot, so an unlensable subject costs one fetch per deploy until it resolves; a negative marker for failed subjects is bean ISNOT-q70n. Editing a review from a listing row posts the lens's title and identifiers back with the poster's old `subject.cid`, so `stale` only clears through `/review`, which re-resolves the cid.
